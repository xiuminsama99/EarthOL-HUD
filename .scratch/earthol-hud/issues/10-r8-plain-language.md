# 10: R8 小白友好轮（纯小白用户反馈产出）

**What to build:** 面向普通用户的语言与体验改造——把"工程师语言"翻译成"人话"，消除文案矛盾，降低理解成本。纯小白用户报告："我会再打开几次，但坚持不了一周——规则藏太深、文案矛盾、问卷长。"

**原则**：引擎语义与领域规则**一律不改**，只改 UI 文案、展示逻辑、交互入口。内部代码标识符可保留（vacationCoins 等），用户可见文案人话化。

**Blocked by:** 05/06（主界面与打卡流程）、01（buildAutoNote 只改文案不改规则）

**Status:** ready-for-agent

## 修复清单（10 项）

### UX-11 文案诚实化
- 「坚持不下去也没关系，系统永不惩罚你」→「漏一天没关系，继续就好」（承诺与实际一致，缺勤回退/重置保留但不再声称"永不惩罚"）
- 位置：OnboardingScreen 欢迎页文案

### UX-12 术语人话化（用户可见文案）
| 术语 | 改为 |
|---|---|
| 等差数列（标签） | 每天只多一点点 |
| 假期币 | 休息券 |
| 最低版本保底 | 今天太累了？做 1 个就算数 |
| 定死（按钮） | 固定目标 |
| 养成值（习惯卡片） | 稳定天数 |
| 动态调节条 | 目标调节 |
| 以身份行动（天面板标签） | 行动天数 |

- 内部类型/变量名不改（vacationCoins、progressStep 等），仅 UI 文案；buildOverachievementNotice 等文案同步人话化

### UX-13 戒除习惯语义修正
- 戒除（反向）习惯：隐藏「多做了 X 个（不建议）」快捷按钮（超额概念对戒除无意义）
- 365 天累计对戒除换说法：`坚持一年，每天能省出 {X} {unit}`（正向保持"365 天累计"）；或戒除时隐藏年度效果行（选清晰方案：换说法）
- 「刚好达标」按钮对戒除仍保留（达标语义 OK）

### UX-14 休息 vs 最低版本区分
- 两个按钮各加一行小字说明：休息（"用 1 张休息券，今天不打卡也不缺勤"）/ 最低版本（"今天太累了？做 1 个就算数，不丢进度"）

### UX-15 引导减负
- 每步加显式「跳过」按钮（审计/反愿景/年度主线/坏习惯可跳过，跳过=空值；身份步保留必填——产品灵魂，但把文案改轻：placeholder 提示"想到什么填什么，之后也能改"）
- 欢迎页文案「用一天时间设定」改「10 分钟设定你的身份」（小白被"一天"吓到）

### UX-16 打卡入口合并
- 卡片内快捷按钮（刚好达标/多做了 N）**点击即直接打卡**（不再只填输入框）
- 卡片内「打卡」按钮保留（给自定义输入量用），底部「一键打卡」=达标快打；两按钮文案区分：卡片内「按输入量打卡」vs 底部「一键打卡（达标）」

### UX-17 打卡语通顺化
- buildAutoNote 重写为通顺人话：如 `今天以{身份}的身份行动了：{习惯名}完成第{actionCount}次（{amount}{unit}），离向往的自己又近了一点点`；超额 `（今天多做了 X 个）` 并入；rest/minimal 文案同步通顺化
- 更新引擎测试断言

### UX-18 热力图未来留白
- HeatmapPanel 未来格子不渲染（留空），避免"像已打卡"误导

### UX-19 诊断面板仅开发模式
- `import.meta.env.DEV` 时显示「诊断面板」，生产构建不渲染（含 App 底部入口）

### UX-20 刚好达标即打卡
- 见 UX-16（快捷按钮直接打卡），「刚好达标」点击=以 target 打卡
