## 🔴 Blocker（必须修）

### UX-1 打卡假达标
- 现象：完成量输入留空 → `Number('')=0`；或低于目标量提交，都提示「今日达标 ✓」，且养成线静默归零、当日锁死
- 修复：
  - `runCheckin` 反馈文案按实际结果分叉：`completedAmount === targetAmount` → 「今日达标 ✓」；未达标 → 「做了 X / 目标 Y，明天继续（未达标当天不计入养成线）」；超额 → 走超额文案
  - 打卡输入拒绝空/0：校验 `amount` ≥ 1 且为整数，否则提示「完成量至少 1」（引擎层 engine 不改——引擎 0 是合法语义（反向习惯触底），UI 层拦截误操作；注意反向习惯 target=0 时一键打卡仍用 plan.target=0 走引擎，不受 UI 校验影响）
- 测试：habitFlow 文案分叉（达标/未达标/超额）；UI 校验逻辑（若入流程层）

### UX-2 作息切换陷阱
- 现象：切换无确认，点击即写 lastScheduleSwitchAt 且当天禁打，文案带「（防作弊）」
- 修复：
  - 切换前 `window.confirm`：「切换作息后今天不能再打卡，确定吗？」
  - 用户可见文案删除「防作弊」字样（保留在代码注释/诊断层）
  - 切换成功反馈改为中性：「已切换为夜间工作，明天起按新作息计算」
- 测试：无逻辑变化（UI 层），流程层校验不动

### UX-3 养成线呈现与哲学冲突
- 现象：「养成线 12/21 · 连续 12 天达标」——与"不做 streak"宣言冲突；缺勤归来清零无解释
- 修复：
  - 文案改为「养成进度 12/21」（删除「连续 X 天达标」）
  - 缺勤归来时（backoffDays > 0）目标框下方提示：「缺勤会重置养成进度，从第 1 天重新计——没关系，继续就是」
- 测试：文案常量断言（若入流程层）

## 🟡 高价值困惑点

### UX-4 引导步数计数错乱
- 现象：计数从 2/6 开始；坏习惯步 6/6、对比图步仍 6/6
- 修复：步骤计数修正为 1..6（欢迎页是否计入以实际结构为准，总步数与 UI 一致，无重复）
- 测试：如无独立逻辑则人工核对（OnboardingScreen 内 step 状态）

### UX-5 休息按钮禁用无提示（移动端无 hover）
- 现象：假期币=0 时按钮禁用，仅 title 提示，移动端点击无反应
- 修复：不禁用；点击时显示反馈「假期币不足：超额打卡可存假期币，存 1 枚即可休息」
- 测试：habitFlow 休息拒绝路径文案（已有 insufficient 拒绝，核对 UI 呈现）

### UX-6 超额警告技术腔
- 现象：「不建议，离目标更远，超额 X 中 Y 已存为假期币（当前 N 枚）。超额当天不计入养成线，连续养成已重新计数」——4 个信息点塞一段
- 修复：简化为两行：「超额 X 已存为假期币（当前 N 枚）——超额当天不计入养成进度」（保留关键信息，去掉"连续养成已重新计数"技术表述）
- 测试：文案断言更新

### UX-7 反向习惯归 0 语义崩坏
- 现象：戒除类习惯目标触底 0，显示「今日目标 0」「365 天累计 0 分钟」
- 修复：目标 = 0 且方向为戒除时，主卡显示完成态：「已戒除到 0，恭喜！可以定死为 0 或换个新习惯」；年度效果文案隐藏或显示「已达成」
- 测试：habitFlow/UI 分支（若入流程层加纯函数 `isZeroTarget` 或复用现有）

### UX-8 天平单位硬编码
- 现象：ScalePanel「累计总量」恒显示"个"，与习惯单位（分钟/元/页）不符
- 修复：用当前习惯的 `unit` 字段替换硬编码「个」（ScalePanel 接收 unit 或习惯信息）
- 测试：文案断言

### UX-9 调试信息裸露
- 现象：主界面直接显示「时间源/业务日」，底部有「地基自检面板（工单 02，诊断用）」
- 修复：「时间源/业务日」两行移入设置区或折叠（保留在界面但默认收起）；「地基自检面板（工单 02，诊断用）」改「诊断面板（开发者用）」
- 测试：无（UI 结构调整）

### UX-10 首屏时间解析慢
- 现象：4 个端点串行 × 3s 超时，弱网最长 12 秒「解析时间中…」
- 修复：timeProvider.refresh 改并行请求（Promise.allSettled 同时打 4 个端点，取最快成功者；全失败降级设备时间）；保持 A1 跨日强制刷新逻辑
- 测试：timeProvider 并行（注入 fetch 模拟并发成功/部分失败）
